Chapter 01

CONNECT DATA SOURCES

Power Query can connect to 200+ sources. Let's start with the 4 most common file types you'll use every day.

i

Connect Excel

Connect to .xlsx, .xls, .xlsm files. Excel is the most common data source in Power BI. You can connect to individual sheets, named ranges, or tables.

Steps
1. Click Get Data → Excel → Browse to your file
2. Navigator opens — shows all sheets & tables
3. Select "Sales_Data" sheet → check preview
4. Check "Select multiple items" if you need multiple sheets
5. Click Transform Data to open Power Query Editor
Real Example

You have a "Monthly_Sales_2024.xlsx" file with 3 sheets: Orders, Customers, Products. Connect all 3 sheets → they appear as 3 separate queries. You can then merge Orders with Customers on CustomerID — just like a SQL JOIN, but with clicks.

ii

Connect CSV

Connect to Comma-Separated Values files. CSV files are plain text — no formulas, no formatting, just raw data. They're the universal format for data exchange between systems.

Steps
1. Click Get Data → Text/CSV
2. Preview window shows delimiter detection (auto-detects comma)
3. Change File Origin to 65001: Unicode (UTF-8) if special characters appear garbled
4. Set Delimiter if not comma (tab, semicolon, pipe)
5. Click Transform Data
Real Example

Your ERP system exports daily stock data as "inventory_20240115.csv". The file has 50,000 rows with columns: SKU, ProductName, Warehouse, Qty, Price. Connect CSV → Power Query reads it in 2 seconds → you can then append yesterday's file, last week's file — building a historical inventory trend.

iii

Connect PDF

Extract tabular data from PDF documents. Power Query scans PDF pages and detects tables. Perfect for extracting data from bank statements, vendor invoices, government reports.

Steps
1. Click Get Data → PDF
2. Navigator shows each page with detected tables
3. Select Table 1 on Page 1 — preview shows extracted data
4. Click Transform Data — clean up column names, remove extra header rows
5. Use Remove Top Rows to delete the PDF's title row that got extracted as data
Real Example

You receive a monthly "HDFC_Bank_Statement_Jan2024.pdf". It has 8 pages of transactions. Power Query extracts a table from each page → you get columns: Date, Description, Debit, Credit, Balance. Clean up the "Page 2 of 8" header rows → you now have bank data ready to merge with your accounting data.

iv

Connect JSON

Connect to JavaScript Object Notation files — the standard format for APIs and web data. JSON uses nested key-value pairs that Power Query automatically parses into tables.

Steps
1. Click Get Data → JSON
2. Power Query shows the JSON structure as a Record or List
3. Click "To Table" in the formula bar to convert a List to a table
4. Click the expand icon (two diverging arrows) on the Record column to extract nested fields
5. Select which nested fields you want as columns
Real Example

You call a weather API and save the response as "weather_delhi.json". It contains: {"city":"Delhi","temp":32,"humidity":65,"forecast":[{"day":"Mon","temp":33},{"day":"Tue","temp":30}]}. Connect JSON → expand the "forecast" list → you get a table with day and temp columns. Now visualize Delhi's weekly weather in Power BI.

Chapter 02

BASIC OPERATIONS

The fundamental actions you'll perform on every dataset — rename, change type, duplicate, and understand Applied Steps

v

Rename Column

Double-click any column header to rename it. Or right-click → Rename. This is the first thing you do after connecting data — fix messy column names.

Example

" Cust_Name " → "Customer Name"
"QTY_SOLD_JAN" → "January Quantity"
"Column1" → "Product Category"

vi

Change Data Type

Click the data type icon in the column header (shows "ABC" for text, "123" for number). Or use the Transform tab. This is critical — wrong types break everything downstream.

Example

Revenue column shows "1,500.00" as Text → Change to Decimal Number → now you can SUM it
Date column shows "15/01/2024" as Text → Change to Date → now you can use time intelligence

vii

Rename Table

Double-click the query name in the left pane. Good naming conventions prevent confusion when you have 20+ queries.

Example

"Sheet1" → "DimCustomer"
"inventory_20240115" → "FactInventory"
"Table 0" → "StgCurrencyExchange"

viii

Duplicate

Right-click a query → Duplicate. Creates a complete independent copy with all applied steps. Useful when you need two versions of the same data with different transformations.

Example

Duplicate "Sales_Data" → rename one to "Sales_Summary" (keep aggregated) and other to "Sales_Detail" (keep all rows). Two queries from one source, different transformations.

ix

Reference

Right-click → Reference. Creates a new query that starts from the output of the original. Changes to the original flow through. This is how you build transformation chains.

Example

Query 1: "RawSales" (connect + clean). Reference it → Query 2: "SalesByRegion" (group by region). Reference again → Query 3: "Top10Products" (filter top 10). Chain of 3 queries, one source of truth.

x

Applied Steps

The most important panel in Power Query. Every action you take is recorded as a step. Think of it as a recipe — Power Query replays these steps on every refresh.

Example — Typical Step Chain
▸ Source — Connected to Excel file
▸ Navigation — Selected "Orders" sheet
▸ Changed Type — Set column data types
▸ Renamed Columns — Fixed 5 column names
▸ Filtered Rows — Removed NULL customer IDs
▸ Removed Duplicates — Based on Order ID

⚠️ Click any step to see data at that point. Delete a step = undo that action. Reorder steps carefully — dependencies matter.

Chapter 03

DATA TYPES

Every column must have the correct data type. Wrong data type = broken calculations, broken visuals, broken everything.

#
i

Whole Number (INT)

Stores integers — no decimals. Used for counts, IDs, quantities. Range: -2 billion to +2 billion.

Examples
OrderID: 10452
Quantity: 7
EmployeeCount: 250
Age: 32
#.
ii

Decimal Number

Stores numbers with decimal precision. Used for money, percentages, rates, measurements. Stores up to 15 significant digits.

Examples
Revenue: 15432.50
TaxRate: 0.18
ExchangeRate: 83.4521
Discount%: 12.5
Ab
iii

Text

Stores any character string. Names, addresses, descriptions, categories. Max 500 million characters. The most common type — and the one most often incorrectly set.

Examples
CustomerName: "Rahul Sharma"
City: "Mumbai"
ProductCode: "ELEC-TV-001"
Email: "rahul@email.com"
iv

Date

Stores dates only (no time). Range: Jan 1, 1900 to Dec 31, 9999. Essential for time intelligence — YEAR(), MONTH(), DAX time calculations all need Date type.

Examples
OrderDate: 15/01/2024
BirthDate: 22/03/1995
HireDate: 01/07/2023
v

Date/Time

Stores both date and time together. Used for transaction timestamps, log data, sensor readings. Power BI stores it as a decimal internally (days since 1900).

Examples
CreatedAT: 15/01/2024 14:32:05
LoginTime: 15/01/2024 09:15:00
SensorRead: 15/01/2024 23:59:59
vi

Boolean (True/False)

Stores only TRUE or FALSE. Used for flags, conditions, binary categorization. In Power Query, also accepts "true"/"false", 1/0, "yes"/"no" as boolean.

Examples
IsActive: TRUE
IsPrimeCustomer: FALSE
HasDiscount: TRUE
IsDeleted: FALSE

Common Mistake: A column shows "1,500" with a comma. Power Query reads it as Text (because of the comma). You change it to Whole Number → it becomes 1500. Always check the data type icon in each column header — "123" = number, "ABC" = text, 📅 = date.

Chapter 04

DATA CLASSIFICATION

Every column in your data is either a Dimension or feeds into a Measure. Understanding this distinction is the foundation of data modeling.

i

Dimension

Dimensions are descriptive attributes that provide context to your data. They answer "Who, What, Where, When". They are stored as columns in your table.

Dimension Examples
→ Customer Name
→ Product Category
→ City / State / Country
→ Order Date
→ Department
→ Status (Active/Inactive)

💡 Dimensions are used to slice, filter, group, and drill your data. Put them on Axis, Legend, and Slicer fields in visuals.

ii

Measure

Measures are calculated values that answer "How Much". They are not stored as columns — they are computed on the fly using DAX formulas based on filter context.

Measure Examples (DAX)
// Total Revenue
Total Revenue = SUM(Sales[Amount])

// Average Order Value
AOV = AVERAGE(Sales[Amount])

// Year to Date Sales
YTD Sales = TOTALYTD(SUM(Sales[Amount]))

// Count of Orders
Order Count = COUNTROWS(Sales)

💡 Measures go in the Values area of visuals. They automatically respond to every filter/slicer — that's their power.

Quick Rule of Thumb

If you can filter by it → it's a Dimension. If you can sum/average/count it → it becomes a Measure. A "Revenue" column in your table is NOT a measure — it's a dimension column with numeric data. You create a Measure called "Total Revenue = SUM(Sales[Revenue])" using DAX. The column is the raw ingredient; the measure is the cooked dish.

Chapter 05

SAVE YOUR WORK

Understanding the .pbix file and the Power BI workflow

What is a .pbix File?

A .pbix file is Power BI's native format. It's a single file that contains everything:

  • Your data model (all tables, relationships, DAX measures)
  • All Power Query transformations (the M code)
  • All report pages and visual configurations
  • Settings, themes, bookmarks, parameters

The Power BI Workflow

1
Get Data
Connect to data sources in Power Query
2
Transform
Clean, reshape, prepare data in Power Query Editor
3
Model
Create relationships, build DAX measures
4
Visualize
Build report pages with interactive visuals
5
Save as .pbix
File → Save As → "Sales_Dashboard.pbix"

Enter Data — Static Data & Master Lookup

Sometimes you don't have a file — you need to type data directly into Power BI. Common for small lookup tables, mapping tables, or parameter lists.

How to Enter Data

1. Click Enter Data in the Home tab
2. A table grid opens — type column names in the header row
3. Type your data row by row
4. Set the table name (e.g., "PriorityMapping")
5. Click Load
Example — Priority Mapping Lookup Table
PriorityCode PriorityName SortOrder
HCritical1
MMedium2
LLow3

Use Case: Your main data has "H", "M", "L" codes. You enter this lookup table, merge it with your main data on PriorityCode → now your report shows "Critical", "Medium", "Low" instead of cryptic codes. Also use SortOrder to ensure "Critical" always appears first in charts.

Refresh — Two Types

Refresh Preview

Click Refresh Preview in Power Query Editor. This only updates the preview you see — it does NOT update the actual data model. Fast, lightweight, for checking your transformations.

Refresh All

Click Refresh All on the Home tab (after closing Power Query Editor). This replays ALL applied steps on the actual source data and updates your data model. This is the real refresh. Use this when source data changes.

Chapter 06

SPLIT COLUMN

7 ways to split a column — from simple delimiters to advanced pattern-based splits

i. Split By Delimiter

Split at a specific character: comma, space, dash, pipe, etc.

Example

Column: "John,Smith,35"
Split by comma → "John" | "Smith" | "35"

ii. Split By Character

Split at every occurrence of a specific character.

Example

Column: "A-B-C-D"
Split by "-" → "A" | "B" | "C" | "D"

iii. Split By Position

Split at fixed character positions — when data has no delimiter but consistent structure.

Example

Column: "20240115DELHI"
Split at positions 0-8 and 8-end → "20240115" | "DELHI"

iv. Lowercase to Uppercase

Split at the transition point from lowercase to uppercase letters. Perfect for camelCase names.

Example

Column: "totalRevenue"
Split at lowercase→uppercase → "total" | "Revenue"
"customerName" → "customer" | "Name"

v. Uppercase to Lowercase

Split at the transition from uppercase to lowercase. For PascalCase or abbreviated codes.

Example

Column: "OrderID"
Split at uppercase→lowercase → "Order" | "ID"
"ProductName" → "Product" | "Name"

vi. Digit to Non-Digit

Split where numbers end and text begins (or vice versa). Extract numbers from mixed strings.

Example

Column: "Order12345"
Split at digit→non-digit → "Order" | "12345"
"Room204B" → "Room" | "204" | "B"

vii. Non-Digit to Digit

Split where text ends and numbers begin. The reverse of the above.

Example

Column: "ABC500"
Split at non-digit→digit → "ABC" | "500"
"Price: 299.99" → "Price: " | "299.99"

Chapter 07

COLUMN & ROW OPERATIONS

Select, remove, keep, sort, replace — the daily operations you'll use on every dataset

Choose Column

Select specific columns from many. Right-click columns → Choose Columns → check the ones you want.

Example

Source has 50 columns. You only need 5: OrderID, Customer, Date, Amount, Status. Choose Column → pick these 5 → 45 columns removed in one step.

Go To Column

Press Ctrl+G or right-click → Go To Column. Type the column name → instantly jumps to it. lifesaver when you have 100+ columns.

Example

Table has 150 columns. You need to check "Customer_Lifetime_Value". Instead of scrolling horizontally forever → Ctrl+G → type "CLV" → it searches and jumps there.

Remove Columns

Select one or more columns (Ctrl+Click for multi-select) → Right-click → Remove Columns. The inverse of Choose Column.

Example

Select "TempColumn", "OldCode", "Notes" → Remove Columns → these 3 are gone. Useful for removing PII columns like SSN before sharing data.

Remove Other Columns

Select the columns you want to KEEP → Right-click → Remove Other Columns. Everything except your selection is deleted.

Example

Select "Date", "Product", "Revenue" → Remove Other Columns → all 47 other columns are gone. Faster than Choose Column when you have few columns to keep.

Keep Top Rows

Home → Keep Rows → Keep Top Rows → Enter number. Keeps the first N rows, removes everything else.

Example

You have 100,000 rows but only need the latest 100 orders for a quick demo dashboard. Keep Top Rows → 100 → done. (Assuming data is sorted by date descending.)

Keep Bottom Rows

Keeps the last N rows. Useful when data is sorted ascending and you want the most recent.

Example

Data sorted oldest-first. You want the last 50 rows (newest transactions). Keep Bottom Rows → 50.

Remove Top Rows

Removes the first N rows. Most common use: removing header rows that Power Query incorrectly detected as data.

Example

CSV export has 3 title rows: "Company Report", "Generated on: Jan 15", "—" followed by actual headers. Remove Top Rows → 3 → then use "Use First Row as Headers".

Remove Bottom Rows

Removes the last N rows. Common for removing footer rows like totals, notes, or disclaimer text.

Example

Excel file has "Grand Total: ₹45,00,000" as the last row and "*Terms & Conditions apply" as the second last. Remove Bottom Rows → 2.

Sort Ascending

Click the column header dropdown → Sort Ascending (A→Z, 1→100, oldest→newest). Or click the A→Z button in the ribbon.

Example

Sort "ProductName" Ascending → Aeropress, Beans, Cup, Grinder, Kettle.... Sort "OrderDate" Ascending → oldest orders first.

Sort Descending

Sort Z→A, 100→1, newest→oldest. Click column header dropdown → Sort Descending.

Example

Sort "Revenue" Descending → ₹5,00,000, ₹3,20,000, ₹1,80,000... — highest first. Sort "OrderDate" Descending → latest orders first.

Use First Row as Headers

Promotes the first row to column headers. The most used button in Power Query. Click it in the Home tab or Transform tab.

Example
Before: Column1="OrderID", Column2="CustomerName", Column3="Amount"
After: OrderID | CustomerName | Amount
The first row values become the actual column names. All other rows shift up by one.

Replace Values (Ctrl+F)

Find and replace values in a column. Shortcut: Ctrl+F in Power Query. Choose which column, what to find, what to replace with.

Example

Column "Status": "N" → Replace with "New"
"P" → Replace with "In Progress"
"D" → Replace with "Delivered"
"NULL" → Replace with "Unknown"
"$" → Replace with "" (remove dollar sign from amounts)

Chapter 08

PIVOT & UNPIVOT

The two most powerful reshaping operations — and the ones that confuse beginners the most

Unpivot Columns

Wide format → Tall format (most common operation)

Unpivot converts columns into rows. This is the #1 transformation in Power Query because most Excel reports are in wide format, but Power BI needs tall format for analysis.

Before Unpivot (Wide — Bad for Power BI)
Country Jan Feb Mar
India100150200
USA300250400
After Unpivot (Tall — Perfect for Power BI)
Country Month Revenue
IndiaJan100
IndiaFeb150
IndiaMar200
USAJan300
USAFeb250
USAMar400
How To Unpivot

Select the columns to unpivot (Jan, Feb, Mar) → Right-click → Unpivot Columns. The non-selected column (Country) stays as-is. Result: two new columns — "Attribute" (the month names) and "Value" (the numbers). Rename them to "Month" and "Revenue".

Pivot Columns

Tall format → Wide format (less common, but needed for crosstabs)

Pivot is the reverse of Unpivot — converts rows into columns. You need to select the column whose values will become new column names, and the column whose values will fill those columns.

Example

You have tall data: Student | Subject | Score (3 rows per student). You want a report card format: Student | Math | Science | English (1 row per student).

Steps: Select "Subject" column → Transform → Pivot Column → Value Column = "Score" → Advanced: choose "Don't Aggregate" (since 1 value per student-subject pair). Result: each subject becomes a column with the score value.

Fill Down

Fills NULL/empty cells with the value from the cell above. Essential for grouped data where only the first row has the group label.

Example

India | Delhi | 100
(null) | Mumbai | 150
(null) | Bangalore | 80
After Fill Down on Country:
India | Delhi | 100
India | Mumbai | 150
India | Bangalore | 80

Round Specific Decimals

Transform → Round → select column → choose decimal places. Cleans up messy decimal values.

Example

15432.58723412 → Round to 2 decimals → 15432.59
83.4521345 → Round to 2 decimals → 83.45
Right-click column → Change Type → Fixed Decimal Number also helps.

Rearrange Columns

Drag column headers left/right to reorder. Or select columns → right-click → Move → To Beginning / To End / Left / Right.

Example

Current order: Status, Amount, Date, Customer
Desired: Date, Customer, Amount, Status
Drag "Date" to first position, "Customer" to second, etc. Good practice: dates first, dimensions next, measures last.

Group By

Transform → Group By. Aggregates rows by a column — like SQL GROUP BY. Choose grouping column and aggregation type.

Example

Group By "Category"
New column: "Total Revenue" → Operation: Sum → Column: Revenue
New column: "Order Count" → Operation: Count Rows
Result: One row per category with total revenue and order count.

Chapter 10

CONNECT FOLDER & AUTOMATE

The game-changer: connect to a folder, and Power Query automatically combines all files — no manual work when new files arrive

Why Connect Folder?

Imagine you receive a new CSV file every day: "sales_20240101.csv", "sales_20240102.csv", .... Instead of connecting each file manually (365 files = 365 connections), you connect to the folder once — Power Query reads ALL files and combines them automatically. When a new file drops in tomorrow? It's automatically included on the next refresh.

Day 1: 5 CSV files
All combined automatically
Day 30: 30 CSV files
Still automatic — zero extra work
Day 365: 365 CSV files
Same single connection — just refresh
1

Connect to Folder

Click Get Data → Folder → Browse to the folder containing your CSV files → Click OK.

What You See

Power Query shows a table with 4 columns: Content (binary/file data), Name (filename like "Superstore_Jan.csv"), Extension (".csv"), Date accessed. This is a list of metadata about each file — NOT your actual data yet.

2

Filter Only CSV Files

Click the filter dropdown on the "Extension" column → Uncheck everything except ".csv". This removes .xlsx, .pdf, .txt, or any other file types in that folder.

Example

Your folder has: readme.txt, sales_jan.csv, sales_feb.csv, summary.xlsx, notes.pdf
After filtering Extension = ".csv": sales_jan.csv, sales_feb.csv — only 2 rows remain. The other files are ignored.

3

Filter Superstore File Name

Click the filter dropdown on the "Name" column → Text Filters → Contains → Type "Superstore". This filters to only files with "Superstore" in the filename.

Example

Folder has: Superstore_Jan.csv, Superstore_Feb.csv, inventory_mar.csv, Superstore_Mar.csv
Filter Name contains "Superstore": Superstore_Jan.csv, Superstore_Feb.csv, Superstore_Mar.csv — "inventory_mar.csv" is excluded.

4

Extract Data Using Double Arrows

This is the magic step. In the "Content" column header, you'll see two green diverging arrows ⇊. Click them. This tells Power Query: "Go inside each file, read the data, and combine everything into one table."

What Happens When You Click Double Arrows
Step 1: Preview Window Appears

Power Query shows a sample of the data from the first file. You see all columns detected. Check the preview — are the right columns showing?

Step 2: Check "Combine Files" at Bottom

At the bottom of the window, you see "Combine Files" is checked. This means: combine data from ALL filtered files (not just the first one). Keep this checked!

Step 3: Click OK

Power Query creates TWO things: a "Sample File" query (template for transformations) and a "Transform File" function (applied to each file). Your combined data appears.

Final Result

Superstore_Jan.csv has 1,000 rows. Superstore_Feb.csv has 950 rows. Superstore_Mar.csv has 1,100 rows. After double arrows: one combined table with 3,050 rows. Plus a bonus column: "Source.Name" showing which file each row came from — perfect for filtering by month!

5

Clean the Sample File (Applies to ALL)

Now here's the real magic: go to the "Sample File" query in the left panel. Any transformation you do here (rename columns, change types, filter rows, remove columns) automatically applies to ALL files.

Example — Transform Once, Apply Everywhere

In Sample File query:
→ Rename "Order ID" to "OrderID"
→ Change "Sales" column to Decimal Number
→ Remove "Row ID" column
→ Filter out rows where Sales = 0

These 4 steps apply to ALL 3 files automatically. You don't touch Feb or Mar's data separately. This is the power of the Folder connector + Sample File pattern.

Pro Tip: After combining, you get a "Source.Name" column showing the filename. Use Split Column → By Delimiter → "_" on it to extract "Jan", "Feb", "Mar" as a separate Month column. Now you can analyze trends across months — all from a folder connection!
