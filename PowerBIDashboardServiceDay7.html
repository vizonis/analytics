Chapter 01

WHAT IS A DASHBOARD?

A single-page canvas that tells a complete data story at a glance

Dashboard — Single Page, Multiple Visuals
Definition

A dashboard is a single-page collection of multiple visuals (KPIs, charts, tables, maps) arranged together to provide a consolidated, at-a-glance view of business performance.

Purpose

Instead of opening 10 separate reports and scrolling through tables, a stakeholder opens one page and immediately sees: revenue trend, headcount, top performers, and regional breakdown — all interconnected through slicers.

Components

Every dashboard has: KPI cards (top metrics), core charts (trend, comparison, composition), detail table (drill-down data), and slicers/filters (interactivity). The mockup on the left shows all four.

Key Rule

A dashboard must fit on one screen — no scrolling. If you need to scroll, it's a report, not a dashboard. Every pixel should earn its place.

Chapter 02

WHY WE NEED DASHBOARDS

Raw data is useless without context — dashboards turn data into decisions

Speed of Insight

A CEO doesn't have 30 minutes to parse a 50,000-row table. A dashboard answers "How are we doing?" in under 5 seconds.

Pattern Recognition

Human brains process visuals 60,000x faster than text. A declining trend line or a red cluster on a map triggers instant understanding.

Self-Service Analytics

Stakeholders click slicers instead of emailing "Can you pull this for Q3?" — reducing the BI team's ad-hoc request load by 70%.

Single Source of Truth

When Sales, Finance, and HR all look at the same dashboard, there are no more "my number vs your number" debates in meetings.

Proactive Alerts

Instead of discovering problems at month-end, dashboards with alerts flag anomalies the moment they happen.

Stakeholder Alignment

Everyone from the intern to the board member looks at the same metrics, creating a shared language of performance.

Chapter 03

DASHBOARD vs INDIVIDUAL VISUAL

One chart answers one question — a dashboard answers the entire meeting

Individual Visual

Single chart in isolation

Single Bar Chart — "Revenue by City"
  • Answers only one question: "Which city has highest revenue?"
  • No context — Is this good? Bad? Compared to what?
  • No filters — Can't slice by year, department, or region
  • No drill-through — Can't click to see employee details

Dashboard

Coordinated multi-visual canvas

Dashboard — Revenue KPI + Chart + Map + Table (all cross-filtered)
  • Answers the full question: "How is revenue performing, where, and vs last year?"
  • Cross-filtering — Click Houston bar → donut, table, KPI all update
  • Slicers — Filter by Year, Department, Region globally
  • Drill-through — Right-click → see employee-level detail page
Chapter 04

DASHBOARD BEST PRACTICES

Rules that separate amateur dashboards from production-grade ones

01

One Screen, No Scroll

If users scroll, you've built a report. Dashboards = 1920×1080 (or 1366×768 for laptops). Every visual must fit without vertical scrolling.

02

5–8 Visuals Maximum

More than 8 visuals creates cognitive overload. Each visual must answer a unique question — no redundant charts.

03

Top-Left Hierarchy

Most important KPIs go top-left (Western reading pattern). Supporting charts middle, detail table bottom-right. Slicers top or left edge.

04

Consistent Color Language

Green = good, Red = bad — across ALL visuals. Don't use green for "HR" in one chart and "above target" in another. One color = one meaning.

05

Remove Chart Junk

No redundant legends, no gridlines unless needed, no 3D effects, no pie charts with 15 slices. If it doesn't add information, delete it.

06

Mobile-First Slicing

Use phone layout (916×540) for mobile views. Rearrange visuals: stack vertically, make slicers prominent, hide low-priority charts.

Chapter 05

TARGET AUDIENCE & UI/UX

Who sees the dashboard determines what the dashboard looks like

C-Suite

CEO, CFO, COO

3-5 KPIs only. Large numbers, trend arrows, red/amber/green. No tables, no drill-downs.

Directors / VPs

Department heads

KPIs + 3-4 charts. Add comparisons, YoY trends, and slicers for their department scope.

Managers

Team leads, supervisors

Full dashboard + drill-through. Tables, details, cross-filtering. They need the "why."

Analysts

Data team, BI devs

Multi-page reports. Raw data access, export options, DAX queries. Not really a "dashboard" user.

UI/UX Principles for Power BI Dashboards

Contrast & Hierarchy

Use font size (24px KPI vs 10px label), weight (bold numbers vs regular text), and color (acid green for key metrics, gray for secondary) to guide the eye. Never use more than 3 font sizes.

Whitespace is a Feature

Padding between visuals = breathing room. 16-24px gaps between cards. Cramped dashboards feel overwhelming. Whitespace signals confidence and clarity.

Dark Background Advantage

Dark themes (#050505, #0A0C10) make colored data pop naturally. Light themes require heavy borders and backgrounds. Always prefer dark for data-dense screens.

Interactive, Not Cluttered

Use tooltips instead of data labels. Use cross-filtering instead of 5 redundant charts. Use bookmarks for different views instead of cramming everything on one page.

Chapter 06

WHAT IS POWER BI SERVICE?

The cloud platform that turns .pbix files into shared, interactive experiences

Power BI Service — app.powerbi.com
What Is It?

Power BI Service (app.powerbi.com) is the cloud-based SaaS platform where you publish, share, collaborate on, and manage Power BI content. It's the bridge between your .pbix file and your audience.

Why We Need It

Desktop is for building. Service is for distributing. Without Service, your dashboards live only on your laptop. With Service, 500 people can view the same dashboard from a browser, phone, or Teams — always showing the latest data.

Key Capabilities

Publish reports from Desktop → Share with users/groups → Subscribe to scheduled emails → Alert on data changes → Embed in Teams/SharePoint → Refresh datasets on schedule.

Access

Requires a Pro ($10/user/mo) or Premium ($20/user/mo) license. Free license can view shared content in Premium capacity workspaces only.

Chapter 09

WORKSPACES

The container for everything — datasets, reports, dashboards, and dataflows

My Workspace

Personal, default

Created automatically. Only you can access. Good for development and testing. Never share from My Workspace in production — it's not backed up, not recoverable if you leave.

Standard Workspace

Team collaboration

Create via "Workspaces" → "+ New workspace". Add members as Admin (full control), Member (edit/publish), Contributor (edit only), or Viewer (read-only). Pro license required for all members.

Premium Workspace

Enterprise, no Pro needed for viewers

Assigned to Premium capacity (P/A/EM) or Fabric capacity (F). Free users CAN view content. Larger dataset sizes (400GB vs 1GB). Dedicated resources = faster refresh, no throttling.

Chapter 10

PUBLISH & VIEW DASHBOARDS

From your laptop to your stakeholder's browser — in 3 clicks

How to Publish — From Power BI Desktop
1

Open your .pbix file in Power BI Desktop

Make sure all visuals are finalized, bookmarks are set, and the dashboard looks good at 1920×1080 resolution.

2

Click Publish button (Home ribbon)

A dialog opens showing your workspaces. Select the target workspace (e.g., "HR Analytics"). Click Select. A progress bar appears.

3

Success! Click the link to open in browser

Power BI Desktop shows "Success" with a "Open 'HR Report' in Power BI" link. Click it → browser opens → your report is live in the workspace. Note: Dashboards are created from pinning visuals, not published directly.

How to View a Dashboard in Power BI Service
1

Go to app.powerbi.com and sign in

Use your work email (the one with Pro/Premium license). If your org uses SSO, you'll be auto-authenticated.

2

Navigate to the workspace

Left nav → Workspaces → click the workspace name. Or find it under "Recent" / "Frequent" on the Home page.

3

Click the Dashboard tile to open it

Dashboard opens in Reading View by default. Interact with slicers, hover for tooltips, click visuals for cross-filtering. Click "Edit" for Edit View (if you have permissions).

Important: Report vs Dashboard in Service

When you Publish from Desktop, you publish a Report (multi-page, interactive). A Dashboard is a separate entity in Service — you create it by pinning tiles from a report onto a dashboard canvas. Dashboard = single page, fixed tiles. Report = multi-page, full interactivity.

Chapter 11

PROPERTIES OF REPORT

Metadata, storage, and configuration settings for published reports

Report Settings & Properties — Where to Find Them
How to Access

Open report in Service → Click "⋯" (More options) → Settings. Opens a side panel with all properties. Also accessible from workspace list → "⋯" on the report tile.

Change Dataset

Under Settings → Dataset → "Change dataset". Useful when you want to swap a dev dataset for a prod dataset without republishing. Both datasets must have identical schema.

Enhanced Tooltips

Toggle ON in Settings. Lets you design custom tooltip pages in Desktop (small 320×280 pages with their own visuals) that appear on hover instead of the default tooltip.

Personalize Visuals

Toggle ON. Lets viewers temporarily change chart type, colors, and measures — without editing the report. Changes are per-user and don't save. Great for execs who want to "try a different view."

Chapter 12

DOWNLOAD OPTIONS

Export dashboards and reports as PDF, PowerPoint, or Analyse in Excel

Download as PDF

Exports the current view (with current filter context) as a static PDF document.

Steps

Open report → File → Download as PDF → Choose orientation (Landscape/Portrait) → Choose "Current page" or "All pages" → Adjust wallpaper/background → Download.

Tip: PDF captures the exact visual state including filters. But it's a snapshot — no interactivity after export.

Export to PowerPoint

Each report page becomes a PowerPoint slide with visuals as images.

Steps

Open report → File → Export to PowerPoint → Choose "Current page" or "All pages" → Each visual becomes an editable image in PPTX → Download.

Tip: Perfect for board presentations. Visuals are high-res PNGs. You can add your own text/bullets around them in PowerPoint.

Analyse in Excel

Opens an Excel workbook connected live to the Power BI dataset via PivotTables.

Steps

Open report → "⋯" More options → "Analyse in Excel" → Excel opens with a PivotTable Field List connected to your dataset → Drag fields to build your own analysis.

Tip: This is not a static export — it's a live connection. Changes to the dataset (after refresh) reflect in Excel. Requires Excel desktop app (not web version).

Chapter 13

SUBSCRIPTIONS

Automated email delivery of dashboard snapshots on a schedule you define

Subscribe to This Report — Dialog
How to Create a Subscription

Open report in Service → Click "Subscribe" (top bar) or "⋯" → "Subscribe to this report". The subscription dialog opens (shown left).

Schedules

Choose frequency: Daily (once per day), Weekly (pick day(s)), or Monthly (pick date). Set time and timezone. The email fires at the scheduled time with the latest data (after last refresh).

Attach Report

Toggle "Attach current page" to include a PNG snapshot of the report in the email. Recipients don't need a Power BI license to view the attached image. Without attachment, they need Pro to click through.

Recipients

Add email addresses (internal or external). External recipients receive the attachment but cannot click through to the Power BI Service. Use distribution lists for teams. You can add up to 50 recipients per subscription.

Prerequisites

Requires Pro or Premium license for the creator. The workspace must have a gateway connection if data source is on-premises (otherwise refresh fails before email fires). Dataset must refresh before the subscription time.

Chapter 14

ALERTS

Get notified automatically when a metric crosses your defined threshold

Manage Alerts — Dialog
How to Add an Alert

In Power BI Service, open a report → right-click on a KPI card, gauge, or card visual → select "Manage alerts". The alert dialog opens. Note: Alerts only work on card, gauge, KPI, and indicator visuals — not bar charts or line charts.

Setting the Threshold

Set a condition: "Above" or "Below" a specific number. Example: "Alert me when Total Headcount drops below 1,200." The alert checks once per day after the dataset refreshes — it's not real-time.

Email Notifications

When the threshold is crossed, Power BI sends an email to your registered email. The email includes: the metric name, the current value, the threshold, and a "Click to open" link that takes you directly to the report.

Teams Notifications

In the alert dialog, add a Microsoft Teams webhook URL to also post alerts to a Teams channel. Go to Teams channel → Connectors → Incoming Webhook → copy URL → paste in Power BI alert settings. The alert posts as an adaptive card in the channel.

Limitations

Not real-time — checks once/day after refresh. Card/KPI/Gauge only — no alerts on bar/line/pie charts. Max 50 alerts per user across all dashboards. No custom frequency — you can't choose "check every hour." For real-time, use Data Alerts API or Power Automate.
