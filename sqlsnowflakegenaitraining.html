What is Cortex Analyst?

Snowflake Cortex Analyst is a fully managed, AI-powered feature inside Snowflake that lets you ask questions in plain English and get accurate answers directly from your data — without writing any SQL.

Without Cortex Analyst

  • Write complex SQL queries manually
  • Need to know table names, joins, relationships
  • Business users depend on data team
  • Time consuming for ad-hoc analysis

With Cortex Analyst

  • Ask in plain English: "Total sales by region"
  • AI understands schema & relationships automatically
  • Business users can self-serve instantly
  • Instant insights, no waiting

Simple Analogy

Think of Cortex Analyst as a very smart assistant sitting on top of your database. You ask "How many employees left last year?" and it automatically writes the SQL, runs it, and gives you the answer — all in seconds.

Secure by Design

Data never leaves Snowflake. AI runs inside your account — zero data leakage.

No SQL Needed

Business stakeholders can directly ask questions without knowing SQL syntax.

Accurate Results

Uses semantic models to understand context, ensuring correct aggregations and joins.

Step-by-Step Setup

Follow these exact 7 steps we did in the session to create your own Cortex Analyst.

1

Login to Snowflake

Login with your provided credentials. Then navigate to AI & ML in the left sidebar and select Analyst.

2

Click "Create with Autopilot"

You'll see a button to create a new analyst. Click "Create with Autopilot" — this auto-generates the semantic model for you.

3

Provide Context Screen Skipped

This is an optional screen where you can add business context. We skipped this in our session as it's not required for basic setup.

4

Name the Semantic View

We named it HR_ANALYTICS. Then select the database and schema where this semantic view will be saved.

5

Choose Tables

Select all 5 tables — EMPLOYEES, ATTENDANCE, ATTRITION, DEPARTMENTS, PERFORMANCE. These become the input source for all questions.

6

Select All Columns & Create

For each table, select all columns. Then click "Create". Wait a few seconds for Snowflake to build the semantic model.

7

Add Relationships Critical

Map the relationships between tables (e.g., EMPLOYEES → DEPARTMENTS via DEPARTMENT_ID). This step is crucial — without proper relationships, the AI can't join tables correctly and will give wrong answers.

Snowflake AI Functions

Snowflake Cortex AI Functions let you run AI directly inside SQL queries. No Python, no API keys, no external setup — just write SQL and call the function. We practiced 5 functions in our session.

1

SNOWFLAKE.CORTEX.COMPLETE()

Text Generation / Chat Completion

What it does

Generates human-like text responses for any prompt you give it. Think of it as ChatGPT but running inside your Snowflake SQL worksheet. You specify which model to use (like snowflake-arctic) and the prompt.

Why use it

Generate summaries, write emails, create documentation, answer questions — all from within your data pipeline. Since it runs inside Snowflake, your data stays secure.

SELECT SNOWFLAKE.CORTEX.COMPLETE( 'snowflake-arctic', 'Tell me what is special about bangalore for first time visitors' );
Output
A detailed paragraph about Bangalore's weather, food, tech culture, parks, and tips for first-time visitors.
2

SNOWFLAKE.CORTEX.SENTIMENT()

Sentiment Analysis

What it does

Analyzes a piece of text and returns whether the sentiment is positive, negative, or neutral. It reads between the lines — understands frustration even without explicit negative words.

Why use it

Analyze customer feedback, product reviews, support tickets, social media mentions at scale. Run it on millions of rows to understand overall customer sentiment without reading each one.

SELECT SNOWFLAKE.CORTEX.SENTIMENT( 'I got my parcel yesterday and i had to followup with many people' );
Output: NEGATIVE
Even though there's no explicit "bad" word, the AI understood that "had to followup with many people" indicates a frustrating experience.
3

SNOWFLAKE.CORTEX.TRANSLATE()

Language Translation

What it does

Translates text from one language to another. You provide the text, source language code, and target language code. Supports 100+ languages.

Why use it

Translate product descriptions, customer communications, support responses, or entire columns of multilingual data. Perfect for global companies with localized content needs.

SELECT SNOWFLAKE.CORTEX.TRANSLATE( 'Welcome to our data analytics course', 'en', -- source: English 'hi' -- target: Hindi );
Output
हमारे डेटा एनालिटिक्स कोर्स में आपका स्वागत है

Common language codes: en (English), hi (Hindi), es (Spanish), fr (French), de (German), ja (Japanese), zh (Chinese), ta (Tamil), te (Telugu), kn (Kannada)

4

SNOWFLAKE.CORTEX.CLASSIFY_TEXT() — Example 1

Text Classification — Support Ticket

What it does

Takes a text input and a list of categories, then classifies the text into the best matching category. It uses AI to understand context — not just keyword matching.

Why use it

Automatically categorize support tickets, customer feedback, emails, or any unstructured text into predefined buckets. Saves hours of manual tagging and routing.

SELECT SNOWFLAKE.CORTEX.CLASSIFY_TEXT( 'I have made a transaction already but its not reflecting', ARRAY_CONSTRUCT('Shipping', 'Payment', 'Technical') );
Output: Payment
The AI correctly identified this as a Payment issue — "transaction" and "not reflecting" relate to payment processing, not shipping or technical problems.
5

SNOWFLAKE.CORTEX.CLASSIFY_TEXT() — Example 2

Text Classification — HR Query

Same function, different domain

Here we used the same CLASSIFY_TEXT but for an HR context — categorizing an employee query into the right department category. This shows the function is domain-agnostic.

SELECT SNOWFLAKE.CORTEX.CLASSIFY_TEXT( 'I want to take multiple sick leave but i dont know whether my company allows me to take', ARRAY_CONSTRUCT('Onboarding', 'HR Policy', 'Project') );
Output: HR Policy
Correctly classified as HR Policy — "sick leave" and "company allows" are policy-related, not about onboarding or projects.

Real-world use: You can run CLASSIFY_TEXT on an entire column of support tickets in a single query: SELECT ticket_text, CLASSIFY_TEXT(ticket_text, ARRAY_CONSTRUCT('Billing', 'Technical', 'General')) FROM tickets

Section 8

Must-Know SQL Topics for Interviews

AI is the future, but SQL is the foundation. You cannot build AI solutions without solid SQL. These are the topics that appear in 90% of data interviews. Master them thoroughly.

SELECT retrieves data from tables. Every query starts with SELECT.

-- Select all columns SELECT * FROM employees; -- Select specific columns SELECT first_name, last_name, salary FROM employees; -- Select with alias SELECT salary AS monthly_salary, salary * 12 AS annual_salary FROM employees; -- Select distinct values SELECT DISTINCT city FROM employees;
Interview Tip: Always specify column names instead of SELECT * in production. Interviewers check this.

WHERE filters rows based on conditions. Master every operator.

-- Comparison: =, >, <, >=, <=, != SELECT * FROM employees WHERE salary > 50000; -- BETWEEN SELECT * FROM employees WHERE salary BETWEEN 40000 AND 80000; -- IN SELECT * FROM employees WHERE city IN ('Bangalore', 'Mumbai', 'Delhi'); -- LIKE (pattern matching) SELECT * FROM employees WHERE first_name LIKE 'R%'; -- starts with R SELECT * FROM employees WHERE email LIKE '%@gmail.com'; -- IS NULL / IS NOT NULL SELECT * FROM employees WHERE department_id IS NULL; -- Logical: AND, OR, NOT SELECT * FROM employees WHERE city = 'Bangalore' AND salary > 60000; SELECT * FROM employees WHERE city = 'Bangalore' OR city = 'Mumbai';
Interview Tip: Know the difference between WHERE and HAVING. WHERE filters rows before GROUP BY, HAVING filters groups after.
-- Ascending (default) SELECT * FROM employees ORDER BY salary ASC; -- Descending SELECT * FROM employees ORDER BY salary DESC; -- Multiple columns SELECT * FROM employees ORDER BY city ASC, salary DESC; -- With LIMIT SELECT * FROM employees ORDER BY salary DESC LIMIT 5;
SELECT COUNT(*) AS total_employees, COUNT(DISTINCT city) AS unique_cities, SUM(salary) AS total_salary, AVG(salary) AS avg_salary, MIN(salary) AS min_salary, MAX(salary) AS max_salary FROM employees; -- With GROUP BY SELECT city, COUNT(*) AS emp_count, AVG(salary) AS avg_sal FROM employees GROUP BY city; -- With HAVING SELECT city, COUNT(*) AS emp_count FROM employees GROUP BY city HAVING COUNT(*) > 10;
Interview Tip: COUNT(*) counts all rows including NULLs. COUNT(column_name) excludes NULLs. This is a very common interview question!
SELECT UPPER(first_name), -- Convert to uppercase LOWER(email), -- Convert to lowercase CONCAT(first_name, ' ', last_name), -- Concatenate strings SUBSTRING(email, 1, 5), -- Extract characters LENGTH(first_name), -- String length TRIM(' hello '), -- Remove leading/trailing spaces REPLACE(email, '@', '[at]'), -- Replace substring LEFT(phone, 4), -- First 4 characters RIGHT(phone, 4) -- Last 4 characters FROM employees;
SELECT CURRENT_DATE(), -- Today's date CURRENT_TIMESTAMP(), -- Current date + time YEAR(hire_date), -- Extract year MONTH(hire_date), -- Extract month (1-12) DAY(hire_date), -- Extract day DATEDIFF('day', hire_date, CURRENT_DATE()), -- Days between dates DATEADD('year', 1, hire_date), -- Add 1 year DATE_TRUNC('month', hire_date) -- Truncate to month start FROM employees;
Interview Tip: "Find employees with > 5 years experience" = DATEDIFF('year', hire_date, CURRENT_DATE()) > 5. Very commonly asked.
-- CASE WHEN (most important!) SELECT first_name, salary, CASE WHEN salary >= 80000 THEN 'High' WHEN salary >= 50000 THEN 'Medium' ELSE 'Low' END AS salary_band FROM employees; -- COALESCE (return first non-null value) SELECT COALESCE(phone, mobile, email, 'N/A') AS contact FROM employees; -- IFF (Snowflake's inline IF) SELECT IFF(salary > 60000, 'Above Avg', 'Below Avg') FROM employees; -- NULLIF (returns NULL if values match) SELECT NULLIF(status, 'N/A') FROM employees;
Interview Tip: CASE WHEN is asked in 80% of interviews. Practice creating buckets, flags, and conditional calculations.

Window functions perform calculations across a set of rows related to the current row — without collapsing the rows like GROUP BY.

SELECT first_name, city, salary, ROW_NUMBER() OVER(ORDER BY salary DESC) AS row_num, RANK() OVER(ORDER BY salary DESC) AS rank, DENSE_RANK() OVER(ORDER BY salary DESC) AS dense_rank, NTILE(4) OVER(ORDER BY salary DESC) AS quartile FROM employees; -- Partition by city SELECT first_name, city, salary, RANK() OVER(PARTITION BY city ORDER BY salary DESC) AS city_rank FROM employees;

Interview Tip: "Find the 2nd highest salary" → ROW_NUMBER = 2. "Top 3 employees per department" → PARTITION BY + RANK. These are guaranteed questions!
-- INNER JOIN (only matching rows from both tables) SELECT e.first_name, d.department_name FROM employees e INNER JOIN departments d ON e.department_id = d.department_id; -- LEFT JOIN (all from left + matching from right) SELECT e.first_name, d.department_name FROM employees e LEFT JOIN departments d ON e.department_id = d.department_id; -- Employees without department will show NULL for department_name -- RIGHT JOIN (all from right + matching from left) SELECT e.first_name, d.department_name FROM employees e RIGHT JOIN departments d ON e.department_id = d.department_id; -- Departments without employees will show NULL for first_name -- FULL OUTER JOIN (all rows from both tables) SELECT e.first_name, d.department_name FROM employees e FULL OUTER JOIN departments d ON e.department_id = d.department_id; -- CROSS JOIN (every combination — Cartesian product) SELECT e.first_name, d.department_name FROM employees e CROSS JOIN departments d; -- SELF JOIN (join table with itself) SELECT e1.first_name AS employee, e2.first_name AS manager FROM employees e1 LEFT JOIN employees e2 ON e1.manager_id = e2.employee_id;
Interview Tip: "Find departments with no employees" → LEFT JOIN + WHERE right_column IS NULL. "Find employees not in any department" → same pattern. These are top-5 most asked join questions.
