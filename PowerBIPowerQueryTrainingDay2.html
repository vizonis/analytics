Chapter 01

EXTRACT

Pull out specific parts of a text string — first few characters, last few, a range, or everything around a delimiter

i

First Characters

Transform → Extract → First Characters → Enter count. Pulls N characters from the beginning of each value.

Example
"IN-DEL-001" → First 2 → "IN"
"91-9876543210" → First 2 → "91"

Use Case: Extract country code "IN", "US", "UK" from a combined country-code-id column. Or extract area code from phone numbers.

ii

End Characters

Transform → Extract → End Characters → Enter count. Pulls N characters from the end of each value.

Example
"INV-2024-001" → End 3 → "001"
"₹15,00,000.00" → End 2 → "00"

Use Case: Extract serial number from invoice codes, extract file extension from filenames (.csv, .xlsx).

iii

Range

Transform → Extract → Range → Enter starting position and count. Pulls N characters from a specific position.

Example
"20240115-DELHI" → Start 1, Count 4 → "2024"
"20240115-DELHI" → Start 5, Count 2 → "01"

Use Case: Extract year, month, day from a date string "20240115". Start 1,4 = Year. Start 5,2 = Month. Start 7,2 = Day.

iv

Length

Transform → Extract → Length. Returns the number of characters in each value. Doesn't extract — it calculates length as a new column.

Example
"Rahul" → Length → 5
"9876543210" → Length → 10
"" (empty) → Length → 0

Use Case: Validate phone numbers (should be 10 digits), validate PIN codes (should be 6), find empty strings (length = 0).

v

Text Before Delimiter

Extract everything before a specific character. One of the most used extract functions.

Example
"John.Smith@email.com" → Before "@" → "John.Smith"
"Delhi, India, 110001" → Before "," → "Delhi"
"Product: Laptop" → Before ": " → "Product"

Use Case: Extract username from email, extract first value from comma-separated lists, extract label from "Label: Value" patterns.

vi

Text After Delimiter

Extract everything after a specific character. The twin of "Before Delimiter".

Example
"John.Smith@email.com" → After "@" → "email.com"
"Product: Laptop" → After ": " → "Laptop"
"Price: ₹45,000" → After ": " → "₹45,000"

Use Case: Extract domain from email, extract value from "Key: Value" pairs, extract amount after currency symbol.

vii

Text Between Delimiters

Extract everything between two delimiters. You specify the start delimiter and end delimiter.

Example 1
"[OrderID: 10452]"
Start delimiter: "[OrderID: "
End delimiter: "]"
→ Between → "10452"
Example 2
"Name: Rahul | Age: 30"
Start delimiter: "Name: "
End delimiter: " |"
→ Between → "Rahul"

Use Case: Extract values from bracketed text [like this], extract data between XML/HTML tags, pull values from structured log messages like "[ERROR] Message: something failed at Line:42".

Chapter 02

CASE TRANSFORMATIONS

Change the casing of text — normalize messy data into a consistent format

AB

Upper Case

Transform → Format → Upper Case. Converts all characters to UPPERCASE.

Example
"john doe" → "JOHN DOE"
"New Delhi" → "NEW DELHI"

Use Case: Standardize country codes ("in" → "IN"), state codes, category codes for consistent matching.

ab

Lower Case

Transform → Format → Lower Case. Converts all characters to lowercase.

Example
"JOHN DOE" → "john doe"
"Hello WORLD" → "hello world"

Use Case: Normalize emails for deduplication ("Rahul@email.com" and "rahul@email.com" should match).

Ab

Capitalize Each Word

Transform → Format → Capitalize Each Word. First letter of every word becomes uppercase, rest lowercase. Also called Title Case or Proper Case.

Example
"john doe" → "John Doe"
"NEW DELHI" → "New Delhi"
"mUMBAI, mAHARASHTRA" → "Mumbai, Maharashtra"
Watch Out
"O'BRIEN" → "O'brien" ⚠️
"MCDONALD'S" → "Mcdonald'S" ⚠️

Apostrophes break this function. For names with apostrophes, you'll need manual Replace Values after capitalizing.

Chapter 03

PREFIX & SUFFIX

Add text before or after every value in a column — without complex formulas

Prefix

Transform → Format → Prefix

Adds a fixed text string to the beginning of every value in the column.

Examples
"9876543210" + Prefix "+91-" → "+91-9876543210"
"Laptop" + Prefix "CAT-" → "CAT-Laptop"
"1500" + Prefix "$" → "$1500"

Use Case: Add country codes to phone numbers, add category prefixes to product codes, add currency symbols.

Suffix

Transform → Format → Suffix

Adds a fixed text string to the end of every value in the column.

Examples
"Rahul" + Suffix "@company.com" → "Rahul@company.com"
"1500" + Suffix " USD" → "1500 USD"
"Q1" + Suffix " 2024" → "Q1 2024"

Use Case: Generate email addresses from employee names, add units to measurements (" kg", " cm"), add year to quarter codes.

Pro Tip: Prefix + Suffix can be combined with Extract. First extract the username from "John.Smith@email.com" (Text Before "@" → "John.Smith"), then Suffix "@vizonis.com" → "John.Smith@vizonis.com". Chain transformations for powerful results.

Chapter 04

DATE TRANSFORMATIONS

Extract every component from a date — year, month, quarter, day, week — and calculate age & duration

For all examples below, our sample date value is:

15/01/2024 (January 15, 2024 — a Monday)

Year

Add Column → Date → Year → Year

15/01/2024 → 2024

Use: Group sales by year, create year-over-year comparisons.

Month

Add Column → Date → Month → Month

15/01/2024 → 1

Use: Month-over-month analysis, seasonal trends, fiscal month grouping.

Start of Month

Add Column → Date → Month → Start of Month

15/01/2024 → 01/01/2024

Use: Calculate MTD (Month-to-Date) by comparing each date to start of month.

End of Month

Add Column → Date → Month → End of Month

15/01/2024 → 31/01/2024

Use: Find how many days remain in month, calculate deadlines, determine billing periods.

Days in Month

Add Column → Date → Month → Days in Month

15/01/2024 → 31
15/02/2024 → 29 (leap year!)

Use: Calculate daily average by dividing monthly total by days-in-month.

Quarter

Add Column → Date → Quarter → Quarter

15/01/2024 → 1
15/07/2024 → 3

Use: Q1-Q4 grouping, quarterly revenue reports, fiscal quarter comparisons.

Name of Month

Add Column → Date → Month → Name of Month

15/01/2024 → "January"

Use: Display "January" instead of "1" on chart axis labels for readability.

Week Day

Add Column → Date → Day → Day of Week

15/01/2024 → 1 (Monday = 1)
20/01/2024 → 6 (Saturday = 6)

Use: Flag weekends (6,7), calculate weekday vs weekend sales patterns.

Name of Day

Add Column → Date → Day → Name of Day

15/01/2024 → "Monday"

Use: Show "Monday" instead of "1" on charts, group by day name for heatmap analysis.

Week of Year

Add Column → Date → Week → Week of Year

15/01/2024 → 3 (3rd week of 2024)

Use: "Week 3 sales were ₹50L" — compare week-over-week performance.

Week of Month

Add Column → Date → Week → Week of Month

15/01/2024 → 3 (3rd week of January)

Use: "Week 1 of month typically has highest orders" — analyze intra-month patterns.

Age

Add Column → Date → Age

Calculates the age in years between a date column and today's date. Perfect for calculating employee age, customer age, asset age.

Example
DOB: 22/03/1995 → Age → 28 (as of 2024)
DOB: 15/08/1988 → Age → 35
Hire Date: 01/07/2020 → Age → 3 (tenure in years)

Duration.Days

Subtract two date columns

Calculate the difference in days between two dates. Unlike Age (which returns years), this returns the exact number of days.

How To Do It

Add Column → Custom Column → Formula:

Duration.Days( [EndDate] - [StartDate] )
Examples
Order: 01/01/2024 → Delivery: 05/01/2024
Duration.Days = 4 days
Invoice: 15/12/2023 → Payment: 20/01/2024
Duration.Days = 36 days (payment delay)

Use Case: Order-to-delivery time, payment delay analysis, project duration, employee tenure in days, SLA compliance tracking.

Chapter 05

LOGICAL TRANSFORMATIONS

Conditional logic in Power Query — IF ELSE and Nested IF using Custom Columns with M formula language

IF ELSE

Add Column → Custom Column

The most fundamental conditional logic. Power Query uses M language syntax: if [condition] then [true_value] else [false_value]. Note: NO commas — M language uses then/else keywords, not Excel's IF(condition, true, false).

Syntax
if [ColumnName] then "Value A"
else "Value B"
With Comparison
if [Revenue] >= 10000
then "High Value"
else "Low Value"
Real Examples
Example 1: Categorize Revenue
// New column: "Revenue Category"
if [Revenue] >= 50000 then "Platinum"
else if [Revenue] >= 20000 then "Gold"
else if [Revenue] >= 5000 then "Silver"
else "Bronze"
Input: Revenue = 35000 → Output: "Gold"
Example 2: Check Null Values
// New column: "Email Status"
if [Email] = null then "Missing"
else "Available"
Input: Email = null → Output: "Missing" | Input: Email = "rahul@email.com" → Output: "Available"
Example 3: Date-Based Logic
// New column: "Order Priority"
if Date.DayOfWeek([OrderDate]) >= 6
then "Weekend Order"
else "Weekday Order"
Input: OrderDate = 20/01/2024 (Saturday, day 6) → Output: "Weekend Order"

Nested IF ELSE

Multiple conditions chained together

When you have more than 2 outcomes, chain else if blocks. Each condition is checked top-to-bottom — the first match wins. Power Query doesn't have a SWITCH function like DAX, so nested IF is your only option.

Syntax Pattern
if [Col] = "A" then "Result 1"
else if [Col] = "B" then "Result 2"
else if [Col] = "C" then "Result 3"
else "Default Result"
With AND/OR Conditions
if [Revenue] >= 10000
  and [Qty] >= 50
then "Bulk Premium"
else if [Revenue] >= 10000
then "Premium"
else if [Qty] >= 50
then "Bulk"
else "Standard"
Real Example — Employee Band Calculation
// New column: "Salary Band"
if [AnnualSalary] >= 2500000 then "Band E - Director"
else if [AnnualSalary] >= 1800000 then "Band D - Senior Manager"
else if [AnnualSalary] >= 1200000 then "Band C - Manager"
else if [AnnualSalary] >= 700000 then "Band B - Lead"
else if [AnnualSalary] >= 400000 then "Band A - Associate"
else "Band T - Trainee"
₹30,00,000 → Band E
₹15,00,000 → Band C
₹3,50,000 → Band T

Common Mistakes:
❌ Using commas: if [x] > 5, "Yes", "No" — This is Excel syntax, NOT Power Query!
✅ Using then/else: if [x] > 5 then "Yes" else "No" — Correct M language syntax.
❌ Forgetting to handle null: if [Revenue] > 1000 then "High" — Crashes if Revenue is null.
✅ Handle nulls: if [Revenue] = null then "N/A" else if [Revenue] > 1000 then "High" else "Low"

Chapter 06

MERGE QUERY

Combine two tables based on a common column — Power Query's version of SQL JOINs

How Merge Query Works

Home → Merge Queries

1. Click Merge Queries (merge into current query) or Merge Queries as New (creates a new query)
2. Select the second table from the dropdown
3. Click the matching column in the left table (e.g., CustomerID), then click the matching column in the right table. They'll highlight in green.
4. Choose the Join Kind from the dropdown (Left, Right, Full Outer, Inner)
5. Click OK — a new column appears with a "Table" link in each row
6. Click the expand icon (two diverging arrows ⇊) on the new column → Select which columns you want from the second table → Click OK

Chapter 07

JOIN TYPES

4 types of joins — each returns different data based on what matches and what doesn't

i

INNER JOIN

Only matching rows from BOTH tables. Non-matching rows are dropped.

The strictest join. If a CustomerID exists in Orders but NOT in Customers — it's gone. If a CustomerID exists in Customers but NOT in Orders — gone. Only C1, C2, C3 survive.

Orders (Left)
C1 — 101 — 5000
C2 — 102 — 3000
C3 — 103 — 7000
C5 — 104 — 2000 ✗ DROPPED
Customers (Right)
C1 — Rahul — Delhi
C2 — Priya — Mumbai
C3 — Amit — Bangalore
C4 — Sneha — Chennai ✗ DROPPED
Result — 3 Rows
OrderIDCustomerIDAmountNameCity
101C15000RahulDelhi
102C23000PriyaMumbai
103C37000AmitBangalore
When to Use

When you ONLY want data that has a valid match in both tables. Example: Orders where the customer exists in the master customer list. Orphan orders (C5) and customers with no orders (C4) are excluded. This is the safest join — no null values in the result.

ii

LEFT JOIN

ALL rows from left table + matching rows from right. No match = null.

The most commonly used join (80% of merges). Every row from the left table (Orders) is kept. If there's a match in the right table, you get the data. If not, you get null for the right-side columns. C5 survives with null name/city.

Orders (Left) — ALL KEPT
C1 — 101 — 5000 ✓
C2 — 102 — 3000 ✓
C3 — 103 — 7000 ✓
C5 — 104 — 2000 ✓ (no match → null)
Customers (Right)
C1 — Rahul — Delhi ✓
C2 — Priya — Mumbai ✓
C3 — Amit — Bangalore ✓
C4 — Sneha — Chennai ✗ IGNORED
Result — 4 Rows
OrderIDCustomerIDAmountNameCity
101C15000RahulDelhi
102C23000PriyaMumbai
103C37000AmitBangalore
104C52000nullnull
When to Use

Default choice for 80% of scenarios. You never want to lose orders — even if the customer data is missing. The null values in the last row tell you: "Order 104 has a CustomerID (C5) that doesn't exist in the master list" — this is a data quality issue you can now identify and fix.

iii

RIGHT JOIN

ALL rows from right table + matching rows from left. Reverse of Left Join.

Every row from the right table (Customers) is kept. If there's no matching order, you get null for order columns. C4 (Sneha) survives with null order data. C5 from Orders is dropped because it has no match.

Orders (Left)
C1 — 101 — 5000 ✓
C2 — 102 — 3000 ✓
C3 — 103 — 7000 ✓
C5 — 104 — 2000 ✗ DROPPED
Customers (Right) — ALL KEPT
C1 — Rahul — Delhi ✓
C2 — Priya — Mumbai ✓
C3 — Amit — Bangalore ✓
C4 — Sneha — Chennai ✓ (no match → null)
Result — 4 Rows
OrderIDCustomerIDAmountNameCity
101C15000RahulDelhi
102C23000PriyaMumbai
103C37000AmitBangalore
nullC4nullSnehaChennai
When to Use

When you want to answer: "Which customers have never placed an order?" The last row shows Sneha (C4) with null order data — she's in the customer list but has zero orders. Pro Tip: In practice, most people just swap the tables and use a Left Join instead of a Right Join — it's less confusing.

iv

FULL OUTER JOIN

ALL rows from BOTH tables. Matches where possible, nulls where not.

The most inclusive join. Nothing is dropped. Every row from both tables appears in the result. C5 (no customer match) gets null for name/city. C4 (no order match) gets null for order data. 5 rows total — all data preserved.

Orders (Left) — ALL KEPT
C1 — 101 — 5000 ✓
C2 — 102 — 3000 ✓
C3 — 103 — 7000 ✓
C5 — 104 — 2000 ✓ (null right)
Customers (Right) — ALL KEPT
C1 — Rahul — Delhi ✓
C2 — Priya — Mumbai ✓
C3 — Amit — Bangalore ✓
C4 — Sneha — Chennai ✓ (null left)
Result — 5 Rows (Nothing Dropped)
OrderIDCustIDAmountNameCity
101C15000RahulDelhi
102C23000PriyaMumbai
103C37000AmitBangalore
nullC52000nullnull
nullC4nullSnehaChennai
When to Use

Data reconciliation / audit scenarios. "Show me EVERYTHING — orders without customers AND customers without orders." Used when you need a complete picture for data quality checks. After this join, filter for rows where Name is null (orders with bad CustomerID) OR Amount is null (customers with no orders) to generate a data quality exception report.

Rule of Thumb: Start with Left Join — it covers 80% of use cases. Use Inner Join only when you strictly need valid matches only. Use Full Outer Join for data audits. Avoid Right Join — just swap tables and use Left Join instead.
