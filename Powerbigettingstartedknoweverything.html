Chapter 01

WHAT IS POWER BI

Understanding the foundation of modern business intelligence

Microsoft Power BI

Power BI is a suite of business intelligence tools developed by Microsoft that allows you to connect to hundreds of data sources, transform raw data into meaningful insights, and create stunning interactive visualizations and reports — all without writing complex code.

What is Data Visualization?

Data Visualization is the graphical representation of data and information. Instead of looking at thousands of rows in a spreadsheet, you see charts, graphs, maps, and dashboards that instantly tell a story. The human brain processes visuals 60,000x faster than text — that's why data visualization is the most powerful skill in analytics.

Chapter 02

THE DATA ANALYTICS JOURNEY

From raw, messy data to beautiful dashboards — here's the complete path every organization follows

STEP 01

Data Discovery

Understanding what data exists, where it lives (databases, APIs, files, cloud), and what questions the business wants answered. This is the exploratory phase where you identify data sources, assess data quality, and map out what's available.

STEP 02

Data Storage

Raw data gets stored in various systems — SQL databases, Azure Data Lake, Excel files, SharePoint, ERP systems like SAP, CRM like Salesforce. The choice of storage depends on data volume, velocity, and the organization's infrastructure.

STEP 03

Data Cleaning (ETL)

Extract → Transform → Load. Raw data is messy — it has duplicates, nulls, wrong formats, inconsistent naming. ETL cleans, reshapes, and prepares data for analysis. In Power BI, this is done using Power Query — no coding required, just drag and drop.

STEP 04

Data Warehouse

A centralized repository optimized for analytics. Unlike operational databases built for transactions, a data warehouse is built for queries. Data from multiple sources is consolidated here in a structured format (star schema, snowflake schema) enabling fast, reliable reporting.

STEP 05 — POWER BI

Reporting & Visualization

This is where Power BI shines. Connect to your clean data, build interactive dashboards with 200+ visual types, add DAX calculations, create drill-through reports, and share insights across your organization. This is the final mile of the data journey — where data becomes decisions.

Chapter 03

WHY POWER BI

Why not just Excel? Why not just SQL? Here's the honest comparison.

Microsoft Excel

Good for small data tasks

  • Row limit: Max 1,048,576 rows per sheet. Your 10 million row sales data? Won't fit.
  • Performance crash: Open a 500K row file with VLOOKUPs — your laptop freezes for minutes.
  • No interactivity: You see a static pivot table. Can't drill down from country → state → city dynamically.
  • Sharing nightmare: Email a 50MB file? Recipient needs same version, same formatting, same data refresh.
  • Manual refresh: Data changes? Manually copy-paste or rebuild connections every time.
  • Best for: Quick ad-hoc analysis, financial modeling, small datasets under 100K rows.

Microsoft Power BI

Built for enterprise analytics

  • No practical row limit: Handles 100 million+ rows smoothly with import mode, and billions in DirectQuery.
  • Blazing fast: VertiPaq engine compresses data 10x and queries in milliseconds. 10M rows? Loads in seconds.
  • Full interactivity: Click a bar chart → all other visuals filter. Drill down, cross-filter, tooltips, bookmarks, buttons.
  • Cloud sharing: Publish to Power BI Service. 1000 people view the same report, always fresh, mobile-friendly.
  • Automatic refresh: Schedule refresh every 15 min, hourly, daily. Data is always live.
  • Best for: Enterprise dashboards, real-time monitoring, sharing insights at scale, any dataset size.

Real Example: A retail company had 3 years of daily transaction data — 4.2 million rows. In Excel, the file was 380MB, took 5 minutes to open, and crashed on filtering. In Power BI, the same data compressed to 45MB, opened in 8 seconds, and cross-filtering was instant. That's the difference.

SQL

The data language, not a visual tool

  • No visuals: SQL returns tables of numbers. You can't create a pie chart or map with SQL alone.
  • No interactivity: Want to filter by date range? Write another query. Change region? Another query.
  • Steep learning curve: Writing complex joins, window functions, CTEs takes months to master.
  • No sharing: You can email query results as CSV. That's not a dashboard — that's a data dump.
  • Best for: Data engineers, backend developers, writing stored procedures, managing databases.

Microsoft Power BI

Visual analytics that speaks SQL underneath

  • 200+ visual types: Bar, line, pie, map, scatter, treemap, waterfall, gauge, KPI cards, custom visuals from marketplace.
  • Full interactivity: Click any visual → everything filters. Slicers, drill-through, bookmarks, tooltips with sub-reports.
  • No SQL needed (mostly): Drag and drop to build queries. Power Query generates SQL behind the scenes. DAX handles calculations.
  • Enterprise sharing: Publish, embed in Teams/SharePoint/websites, row-level security, email subscriptions.
  • Uses SQL underneath: Power BI writes optimized SQL queries to your database. You get the best of both worlds.

Real Example: A business user needed monthly sales by region, product, and customer segment. In SQL, this required 3 joins, a CTE, and GROUP BY — 25 lines of code. Then they exported to Excel and manually created charts. In Power BI: connect → drag Region to map → drag Sales to size → done in 2 minutes. Same result, zero code.

Chapter 05

INSTALLATION & REQUIREMENTS

Get Power BI Desktop running on your machine in minutes

System Requirements

Processor
64-bit (x64) processor — 1 GHz or faster. Recommended: 4+ cores for large models.
RAM
Minimum: 4 GB. Recommended: 8 GB+. For large datasets (100M+ rows): 16-32 GB.
Storage
Minimum: 1 GB available. Recommended: SSD with 10 GB+ free for caching large datasets.
Display
Minimum: 1280×720. Recommended: 1920×1080 or higher for comfortable dashboard building.
Operating System
Windows 10/11 (64-bit). Windows Server 2016+. Not available for macOS — use Parallels/VM or Power BI Service in browser.

How to Install

1
Download from Microsoft
Go to powerbi.microsoft.com → Downloads → Power BI Desktop (Free). Or download from Microsoft Store.
2
Run the Installer
Execute the PBIDesktopSetup.exe file. Follow the wizard — it's a standard Windows install, no special configuration needed.
3
Launch & Sign In
Open Power BI Desktop. Sign in with your Microsoft account (outlook.com, hotmail.com, or corporate account). Free tier works with personal accounts.
4
Start Building!
You'll see the start screen. Click "Get Data" or open a sample report. You're ready to go — completely free.

Pro Tip: Power BI Desktop is 100% free for building reports. You only need a paid license when you want to publish and share reports on Power BI Service. For learning, the free version is all you need.

Chapter 07

POWER BI DESKTOP DEEP DIVE

The heart of Power BI — where all the magic happens

What is Power BI Desktop?

Power BI Desktop is a free Windows application that is your primary authoring tool. It's where you spend 90% of your time as a Power BI developer. You connect to data sources, clean and transform data (Power Query), build data models with relationships, write DAX calculations, and design interactive report pages — all in one unified interface.

When to Use It?

  • Building new reports and dashboards from scratch
  • Connecting to and transforming raw data sources
  • Creating complex DAX measures and calculated columns
  • Designing data models with relationships (1:1, 1:N, M:N)
  • Before publishing to Power BI Service
  • Performance tuning and optimization

The Three Layers Inside Power BI Desktop

01

Power Query

Data Transformation Layer

The ETL engine inside Power BI. Connect to 200+ data sources and transform data without writing code.

  • 200+ connectors (SQL, Excel, Web, API, Azure, Salesforce, SAP...)
  • Drag & drop transformations
  • Remove duplicates, filter rows, split columns
  • Unpivot, merge, append, group by
  • M formula behind the scenes (optional)
02

DAX

Calculation Layer

Data Analysis Expressions — the formula language for custom calculations that go beyond simple aggregations.

  • Measures (dynamic calculations)
  • Calculated columns (row-level)
  • Calculated tables
  • Time intelligence (YTD, MTD, rolling avg)
  • CALCULATE — the most powerful DAX function
03

Visualization Layer

Presentation Layer

The canvas where you design stunning, interactive reports that tell data stories.

  • 200+ built-in visual types
  • Custom themes & formatting
  • Cross-filtering & drill-through
  • Bookmarks, buttons, navigation
  • AppSource custom visuals marketplace

Power Query: The Unsung Hero

Most beginners underestimate Power Query. In reality, 70% of a Power BI developer's work happens in Power Query. It's the most powerful data transformation tool you'll ever use — and it requires zero coding.

How It Works — Just Drag & Drop

1. Click "Get Data" → Choose your source (Excel, SQL, Web, API...)
2. Preview loads — see your data in a table view immediately
3. Right-click a column → Remove, Rename, Change Type, Split, Replace Values
4. Use the ribbon: Merge Queries (like SQL JOIN), Append Queries (like UNION)
5. Click "Close & Apply" — Power Query records every step and replays it on refresh

Why Power Query is Powerful

Reproducible: Every transformation is a recorded step. Refresh = replay all steps automatically on new data.
Fast: Query folding pushes transformations to the source database (SQL WHERE, GROUP BY) — only needed rows are fetched.
Reusable: Reference one query from another. Build a template, apply to 50 files.
M Language: When you outgrow the UI, you can write M formulas for advanced logic. But 95% of the time, the UI is enough.
Cross-Tool: Same Power Query engine in Excel, Power BI, Azure Data Factory, Fabric Data Factory.

Chapter 09

POWER BI ARCHITECTURE

Understanding how everything connects — from tenant to report

Level 1

Power BI Tenant

The top-level container tied to your organization's Microsoft Entra ID (Azure AD). One tenant per organization. All users, workspaces, capacities, and data live within this boundary. Example: contoso.powerbi.com

Level 2

Resource Group

An Azure-level grouping for management and billing. Contains your Power BI capacity resources along with other Azure resources (storage, networking, etc.). Primarily relevant for Premium Capacity management.

Level 3

Capacity

The dedicated compute resources (v-cores, memory) that power your workspaces. Think of it as buying a server in Microsoft's cloud.

Shared Capacity
Free & Pro users (no dedicated compute)
Premium Capacity
P1-P5 (dedicated v-cores & RAM)
Level 4

Domains & Subdomains

Organizational boundaries within your tenant for governance and discovery. A domain = "Sales Analytics", subdomains = "APAC Sales", "EMEA Sales". Helps users find relevant content and IT to manage permissions at scale. (Optional — governance feature)

Level 5

Workspaces

The collaboration container where teams work. Each workspace holds semantic models, reports, dashboards, and dataflows. Think of it as a project folder.

Roles: Admin, Member, Contributor, Viewer — each with specific permissions
Example: "Finance Workspace", "HR Analytics", "Sales Dashboard"
Level 6

What Lives Inside a Workspace

Semantic Model
Your data model with tables, relationships, DAX measures. Formerly called "Dataset".
Reports
Interactive multi-page reports with visuals, built on top of semantic models.
Dashboards
Single-page canvases pinning visuals from multiple reports. Quick overview layer.

How Different Teams Use This Architecture

Finance Team

→ Workspace: "Finance Analytics"

→ Semantic Model: GL, P&L, Cash Flow data

→ Reports: Monthly close, Budget vs Actual

→ Shared with: CFO, Finance dept, Board

Sales Team

→ Workspace: "Sales Analytics"

→ Semantic Model: CRM data, Order data

→ Reports: Pipeline, Win rate, Territory

→ Shared with: VP Sales, Regional Managers

HR Team

→ Workspace: "People Analytics"

→ Semantic Model: Employee, Attrition data

→ Reports: Headcount, Diversity, Turnover

→ Shared with: CHRO, HR Business Partners

Row-Level Security (RLS): Within the same report, Finance sees all regions' data, but North America manager only sees NA data. Sales rep sees only their own deals. This is configured at the Semantic Model level — one report, different views per user. No need to build separate reports for each team.
